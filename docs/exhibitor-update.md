## 已实现与操作顺序

1. 展商登录进入“我发布的会议”，状态筛选、列表动画、个人主页、AI助手保留原型布局。个人主页及发布/修改表单不加入场动画。
2. 六步编辑：基础信息（封面、海报、名称、时间、地点、人数）、详细信息（三个亮点和介绍）、议程、分类资料、效果预览、发布。预览与发布使用不同色系的浅色按钮。
3. 资料分展商介绍、会议资讯、成果展示，支持本地图片及PDF/PPT/PPTX/DOCX/TXT附件；单附件2MB。图片上传前缩放，头像居中裁成160×160；持久化到MySQL，不要求填写图片链接。
4. 预览使用原型三屏轮播和八个栏目；议程时间列、标签、按钮布局沿用原型。展商只读评论、签名和投票结果，无评论/签名输入框。
5. 提交后只生成待审核版本，不向参会者开放。管理员进入“管理中心 → 展商会议与互动审核”，查看完整会议、议程、三类资料和附件后批准或驳回；批准会一并创建正式会议及资料。
6. 未开始会议修改需重新审核，期间正式会议暂停展示；待审核申请可撤销进入修改，撤销记录保留数据库，列表不显示撤销版本。不提供草稿功能；撤销后离开页面，未提交的编辑内容不会自动保存。
7. 进行中的会议可提交议程签到、投票及提问回答，分别进入管理员审核；审核通过后才写入正式签到/投票/公开回答。展商不执行签到核销，不参与投票。签到窗口必须处于议程开始前2小时至议程结束，投票时间须在会议时间内。
8. 真实签到入口二维码可下载，统计来自工作人员核销记录；同一议程不允许重复发布签到。会议中保留已有直播及回放的内嵌展示，未开启时显示提示。
9. 展商AI接口独立于参会者，只提供本人会议汇总与办会规则。模型连接复用组员的 `AiModelClient`，服务端使用独立角色规则。未配置模型或连接失败时使用规则回复，不假称模型回答；页面保留逐字输出。密钥仅在后端 `.env.ai.local`，不要提交Git。

## 前端文件

- `web/src/components/ExhibitorApp.vue`：Vue入口，已审核展商才加载。通过同源iframe隔离原型样式，避免改动其他角色布局。这一版不是把原型重写为Vue组件。
- `web/public/exhibitor/index.html`、`style.css`：原型页面容器及样式。
- `app.js`：表单、资料、会议布局；`v2.js`：最终轮播、动画和原型视觉；`live.js`：真实接口适配、校验、持久化、媒体及AI交互。加载顺序由index.html控制，后者覆盖早期原型处理函数，不要调整顺序。
- `qr.js`：由项目已有qrcode依赖打包的浏览器二维码工具，不手工修改。
- `web/src/components/ExhibitReview.vue`：管理员完整送审检查与批准/驳回。
- 参会者的 `EventList.vue`、`EventCarousel.vue`、`EventDetail.vue` 接入正式会议封面/海报/亮点，未上传图片的历史会议仍使用原有展示。

## 后端与数据

- `ExhibitApi.java`：会议/互动送审、所有权校验、管理员审批、只读结果、个人日程与媒体访问。
- `ExhibitAi.java`：独立展商AI权限和检索上下文。
- `ExhibitImport.java`：一次性接入旧办会申请。通过app_meta迁移标记防止重复导入，原始记录不删除；旧接口禁止再修改已迁移申请。历史申请若缺封面、议程等必填信息，需要展商补齐后提交，管理员不能跳过校验。
- 新表 `exhibit_meetings` 保存送审版本，`exhibit_reviews` 保存签到/投票/回答送审与撤销记录；正式数据继续写原有events/talks/posts/files/attendance/polls/questions表。
- events新增cover、poster、features；polls新增heading。schema.sql和Upgrade执行增量初始化，不清库。
- 所有写操作需要登录Session及X-App-Request请求头。展商只能操作本人会议；管理员审批加行锁并复查状态、时间和关联ID，重复审批/已撤销审批会拒绝。修改议程保留原ID与个人日程；存在签到记录的议程不允许静默删除。

## 主要接口

| 接口 | 用途 |
|---|---|
| GET/POST `/api/exhibitor/meetings` | 本人列表 / 新建或重新提交 |
| POST `/api/exhibitor/meetings/{id}/withdraw` | 撤销待审核会议 |
| POST `/api/exhibitor/meetings/{id}/interactions/{CHECK或POLL或ANSWER}` | 互动送审 |
| POST `/api/exhibitor/interactions/{id}/withdraw` | 撤销待审核互动 |
| GET `/api/exhibit-review` | 管理员待审队列 |
| POST `/api/exhibit-review/meetings/{id}` | 会议审批，body为pass、reason |
| POST `/api/exhibit-review/interactions/{id}` | 互动审批 |
| POST/DELETE `/api/exhibitor/meetings/{id}/plans/{talk}` | 本人日程 |
| GET `/api/exhibitor/meetings/{id}/replays/{talk}` | 本会议已结束议程回放 |
| POST `/api/exhibitor/ai` | 展商问答，body为question |

## 封面、多海报和AI修正

会议表新增cover_title、meeting_type和posters（有序JSON数组），由Upgrade增量添加。展商表单对应coverTitle、meetingType和posters；封面标题可留空，类型可选自动识别。列表使用与参会者相同的类型推断、文字层级及封面色系；已有封面图片在填写自定义文字后也显示文字。新增会议轮播海报可分批上传1—8张，每张源文件5MB以内，支持前移、后移和删除。海报内容直接展示，不再覆盖额外的大标题。审批页面查看全部图片，审核后参会者和展商使用同一顺序；旧poster字段兼容第一张图，旧会议不丢图片。已获准访问的会议仍保留议程及签名墙快捷轮播页。

顶部头像32px、网名和退出按钮合并为紧凑区域，导航取消旧紫色下划线，悬停色、圆角、过渡时长与参会者一致。个人主页和编辑页仍无入场动画。

展商AI将“审核/审查/审批进度”“待回答/带回答/待回复”“签到”“投票结果”分别生成为数据库事实回答：列出审核状态和原因、问题原文、签到场次及实际核销人数、投票题目及各选项票数。多意图可同时回答；待审核回答不再计为待回答，跨议程签到标为人次，多个题目不相加当去重人数。没有记录明确说明，不让模型补数字；未知预计审批时间不推测。普通办会操作仍复用模型接口。
