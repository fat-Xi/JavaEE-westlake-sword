# 管理员原型落地与审批通知交接

更新日期：2026-11-13。实际项目：桌面 `westlake-sword`。本次直接修改项目代码，没有改动独立 HTML 原型、需求 Word 或汇报 PPT。

## 本次实现

- 管理员沿用确认的原型：账户管理、报名审批、会议审批、问答审批、投票审批、评论审批、签名墙审批、发布签到、启动直播、日志管理、运营看板。
- 移除管理员头像、昵称和个人主页入口；账户管理仍指其他用户的注册审批、分类查询和删除，保留原型业务职责。
- 会议资料审核包含基础信息、详细信息、议程、三类展商资料及附件；删除“效果预览”。通过调用原有事务接口同步发布会议、议程和资料，驳回要求填写原因。
- 问答区区分参会者提问与展商回答；其他审批按会议筛选。展商签到申请也保留审核入口。独立报名审批页保留参会报名审核链路。
- 仅可为正在进行的议程新建签到，展示会议、议程时间、地点及状态；禁止重复发布；结果来自实际工作人员核销记录。管理员不执行核销。
- 启动直播按管理员需求保留空白页面，后续开发者接入，未伪装成已完成直播控制。
- 参会者和展商头像左侧新增铃铛、未读数、消息列表、全部已读。账号/会议报名原有通知继续显示，新增会议、问题、展商互动的通过和驳回通知；评论和签名审核继续复用原通知。驳回通知包含原因。
- 消息存入数据库 `notes`，只读本人消息，每15秒刷新；打开列表也刷新。采用轮询，不是即时推送。时间按浏览器本地时区显示。
- 操作日志读取真实 `logs`，不再使用原型演示记录。账户删除为逻辑删除，保留关联业务；禁止删除管理员，删除后旧会话失效。

## 统计口径

| 指标 | 数据来源与口径 |
| --- | --- |
| 公开会议 | 已审核通过且公开的会议；会议记录同时显示审批数据 |
| 平台账户 | `users` 中未逻辑删除的账户，包括待审核账户 |
| 网站浏览 | 新增 `site_views` 表，登录后页面切换/详情进入记录一次，非去重访客；后台定时刷新不增加浏览 |
| 近7天趋势 | `site_views` 按本地日期统计；无记录的日期显示0 |
| 会议浏览 | 原有 `event_info.views`，与网站浏览统计口径不同，不要求两者相加相等 |
| 待处理审批 | 用户、会议、报名、问题、回答、投票、评论、签名、展商签到申请 |
| 签到与互动 | `attendance`、`marks`、`posts` 的真实记录，签到按议程核销人次计算 |

网站浏览从启用采集起记录，没有补造历史访问量；登录前匿名访问暂不统计。页面注明采集开始日期。看板每15秒更新，也会在重新进入时刷新。

## 文件与接口

- `web/src/components/AdminApp.vue`：与展商相同方式承载管理工作台，同源 iframe，不是独立演示数据源。
- `web/public/admin/app.js`、`style.css`：原型布局和样式；`live.js`：真实接口、字段映射、审批、看板与会话处理。没有本地模拟数据库。
- `web/src/components/NotificationBell.vue`：参会者消息组件；`web/public/notifications.js`、`notifications.css`：展商消息组件。
- `AdminDesk.java`：`GET /api/admin/desk` 数据聚合、`POST /api/visits` 浏览记录、`POST /api/admin/users/{id}/delete` 账户删除。
- `ExhibitApi.java`、`ContentApi.java`：审批事务及通知；`Auth.java`、`Api.java`：删除账户会话及登录限制；`ServiceApi.java`：签到发布校验。
- `schema.sql`：新增统计表，启动自动建表；不清空原有数据。

所有写请求仍使用会话及 `X-App-Request: 1`；管理员接口由后端鉴权，不能只依赖隐藏按钮。长通知截断到数据库字段长度，避免审核成功通知写入时导致事务回滚。
